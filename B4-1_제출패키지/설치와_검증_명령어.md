# B4-1 Ubuntu 22.04 설치·검증 명령어

> **주의:** 실행 전 Ubuntu VM/컨테이너 콘솔 접근과 관리자 권한을 확인한다. 현재 패키지는 서버에 설정을 적용한 결과물이 아니라 적용 절차와 Bash 소스다. SSH 변경은 원격 접속이 끊길 수 있으니 기존 세션을 유지하고 새 포트로 먼저 접속을 확인할 것. Docker 컨테이너는 systemd/sshd/UFW/cron 구성이 VM과 달라 동등 환경 여부를 확인할 것.

## 0. 사전 준비

```bash
sudo apt-get update
sudo apt-get install -y openssh-server ufw acl cron iproute2 procps util-linux gzip
sudo systemctl enable --now ssh cron
```

## 1. SSH 20022 및 Root 로그인 차단

Ubuntu OpenSSH는 `/etc/ssh/sshd_config.d/*.conf`도 읽으므로 설정 파일 간 중복·우선순위를 확인한다. 다음 파일에 정의할 때 다른 설정의 우선 적용 여부를 `sshd -T`로 검증한다.

```bash
printf 'Port 20022\nPermitRootLogin no\n' | sudo tee /etc/ssh/sshd_config.d/01-agent-hardening.conf
sudo /usr/sbin/sshd -t
sudo /usr/sbin/sshd -T | grep -E '^(port|permitrootlogin) '
# 현재 원격 연결을 절대 끊지 말고, 방화벽 새 포트 허용 후 SSH 재시작
```

## 2. UFW 인바운드 기본 거부, 지정 두 포트만 허용

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 20022/tcp
sudo ufw allow 15034/tcp
# 기존 allow 규칙이 있다면 목록 번호 확인 후 불필요한 인바운드 허용 제거
sudo ufw status numbered
sudo ufw enable
sudo systemctl restart ssh
sudo ufw status verbose
sudo ss -tulnp | grep -E ':(20022|15034)\b'
# 별도 터미널에서 ssh -p 20022 USER@HOST 테스트 후 구 세션 종료
```

**중요:** 새 포트로 실제 접속되는지 확인하기 전에는 기존 SSH 세션을 종료하지 않는다. 클라우드 보안그룹/호스트 방화벽도 별도로 설정해야 할 수 있다. 앱을 실행하기 전에는 15034 리슨이 없어도 정상이다.

## 3. 사용자·그룹·디렉터리·ACL

```bash
sudo groupadd -f agent-common
sudo groupadd -f agent-core
for u in agent-admin agent-dev agent-test; do id "$u" >/dev/null 2>&1 || sudo useradd -m -s /bin/bash "$u"; done
sudo usermod -aG agent-common,agent-core agent-admin
sudo usermod -aG agent-common,agent-core agent-dev
sudo usermod -aG agent-common agent-test
# agent-test가 기존에 agent-core에 들어가 있었다면 별도로 제거해야 함.
HOME_DIR=/home/agent-admin/agent-app
sudo install -d -m 751 -o agent-admin -g agent-common "$HOME_DIR"
sudo install -d -m 2770 -o agent-admin -g agent-common "$HOME_DIR/upload_files"
sudo install -d -m 2770 -o agent-admin -g agent-core "$HOME_DIR/api_keys"
sudo install -d -m 2750 -o agent-dev -g agent-core "$HOME_DIR/bin"
sudo install -d -m 2770 -o agent-admin -g agent-core /var/log/agent-app
sudo install -d -m 2770 -o agent-admin -g agent-core /var/log/monitor/agent-app/archive
sudo setfacl -m g:agent-common:rwx,d:g:agent-common:rwx,m::rwx,d:m::rwx "$HOME_DIR/upload_files"
sudo setfacl -m g:agent-core:rwx,d:g:agent-core:rwx,m::rwx,d:m::rwx "$HOME_DIR/api_keys" /var/log/agent-app
sudo setfacl -m o::---,d:o::--- "$HOME_DIR/upload_files" "$HOME_DIR/api_keys" /var/log/agent-app
# provided application artifact name/path is unknown until agent-app.zip is supplied
printf 'agent_api_key_test\n' | sudo tee "$HOME_DIR/api_keys/t_secret.key" >/dev/null
sudo chown agent-admin:agent-core "$HOME_DIR/api_keys/t_secret.key"
sudo chmod 640 "$HOME_DIR/api_keys/t_secret.key"
for u in agent-admin agent-dev agent-test; do id "$u"; done
sudo getfacl "$HOME_DIR/upload_files" "$HOME_DIR/api_keys" /var/log/agent-app
sudo -u agent-test test ! -r "$HOME_DIR/api_keys/t_secret.key" && echo 'QA key access denied [OK]'
```

**보안 주의:** 위 키 문자열은 과제에서 지정한 테스트 전용 문자열이다. 실제 비밀키로 재사용하지 않는다. `agent-common` 구성원이 공유 폴더에 접근할 수 있어야 하며, `agent-test`가 `api_keys`와 로그 폴더에 접근할 수 없어야 한다. 사용자를 만든 직후 `id`로 새 그룹 확인하고 필요시 재로그인한다.

## 4. 프로그램 및 Bash 소스 배치

현재 이 과제 설명서에는 `agent-app.zip`의 이름만 있으므로 **별도 원본 앱 ZIP을 확보하여**, 환경에 맞는 Linux 실행 파일(arm64/x86) 또는 실제 `agent_app.py`를 배치한다. 소스의 기본 점검 대상은 `agent_app.py`이며 실행 파일일 경우 `AGENT_APP_PROCESS`에 실제 프로세스명을 넣어야 한다.

```bash
HOME_DIR=/home/agent-admin/agent-app
sudo install -m 750 -o agent-dev -g agent-core scripts/monitor.sh "$HOME_DIR/bin/monitor.sh"
sudo install -m 750 -o agent-dev -g agent-core scripts/report.sh "$HOME_DIR/bin/report.sh"
sudo install -m 750 -o agent-dev -g agent-core scripts/archive_logs.sh "$HOME_DIR/bin/archive_logs.sh"
sudo ls -l "$HOME_DIR/bin/"
```

`agent-admin`이 앱 실행 전 다음 환경변수를 사용하도록 설정한다. `agent-admin` 계정의 `~/.profile`에 설정하거나 실행 직전에 export한다. **cron은 로그인 프로필을 읽지 않으므로 crontab에 명시한다.**

```bash
export AGENT_HOME=/home/agent-admin/agent-app
export AGENT_PORT=15034
export AGENT_UPLOAD_DIR="$AGENT_HOME/upload_files"
export AGENT_KEY_PATH="$AGENT_HOME/api_keys/t_secret.key"
export AGENT_LOG_DIR=/var/log/agent-app
export AGENT_APP_PROCESS=agent_app.py
# 앱 원본에 명시된 정확한 실행 명령으로 일반 사용자 agent-admin에서 실행
# 예: sudo -u agent-admin env AGENT_HOME=... AGENT_PORT=15034 ... python3 /path/to/agent_app.py
# 앱 stdout에서 [OK] 5개, Agent READY 확인 후 다른 터미널에서
ss -ltnp | grep ':15034'
```

## 5. monitor.sh 수동 실행, cron 매분 자동화

```bash
sudo -u agent-admin env AGENT_HOME=/home/agent-admin/agent-app AGENT_PORT=15034 \
  AGENT_APP_PROCESS=agent_app.py AGENT_LOG_DIR=/var/log/agent-app \
  /home/agent-admin/agent-app/bin/monitor.sh
sudo tail -n 5 /var/log/agent-app/monitor.log
```

`sudo crontab -u agent-admin -e`에서 다음 한 줄 추가(실행 파일일 경우 이름 변경):

```cron
* * * * * AGENT_HOME=/home/agent-admin/agent-app AGENT_PORT=15034 AGENT_LOG_DIR=/var/log/agent-app AGENT_APP_PROCESS=agent_app.py /home/agent-admin/agent-app/bin/monitor.sh >> /var/log/agent-app/cron.out 2>&1
```

```bash
sudo crontab -u agent-admin -l
sudo stat -c '%y %s %n' /var/log/agent-app/monitor.log
# 65초 기다린 뒤 확인: sudo tail -n 5 /var/log/agent-app/monitor.log
```

## 6. 보너스 1 및 2

```bash
sudo -u agent-admin /home/agent-admin/agent-app/bin/report.sh
sudo -u agent-admin /home/agent-admin/agent-app/bin/report.sh '2026-10-16 00:00:00' '2026-10-17 23:59:59'
sudo -u agent-admin /home/agent-admin/agent-app/bin/archive_logs.sh
```

시간 기반 보존을 매일 실행하려면 다음 한 줄을 `agent-admin` crontab에 추가한다.

```cron
10 0 * * * AGENT_LOG_DIR=/var/log/agent-app /home/agent-admin/agent-app/bin/archive_logs.sh >> /var/log/agent-app/cron.out 2>&1
```

**로그 정책 관계:** `monitor.sh`의 **용량 기반 회전**은 `monitor.log`, `monitor.log.1` ... `monitor.log.9`를 대상으로 하며, 보너스 압축은 과제에서 지정한 `*.log` 중 오래된 비활성 로그를 대상으로 한다. 활성 로그는 압축에서 제외한다. 따라서 단일 `monitor.log`만 생성하는 환경에서는 보너스 아카이브 대상이 없을 수 있고 이는 오류가 아니다. 생성된 로그 회전 파일(`.1` 등)을 7일 보존·압축하려면 별도의 파일 패턴 정책이 필요하다.

## 7. 증거 화면 캡처 지침

(1) `sshd -T`, `ss -tulnp` → (2) `ufw status verbose` → (3) `id` 3명 → (4) `ls -ld`, `getfacl`, QA 접근 차단 → (5) 제공 앱 부팅 출력 → (6) monitor 수동 실행 출력 → (7) `tail` → (8) `crontab -l`과 65초 간격 `stat`/`tail` → (9) 보너스 리포트·아카이브 실행. 실제 화면 캡처와 환경·시각을 기록하고, 샘플 출력은 증거로 제출하지 않는다.
